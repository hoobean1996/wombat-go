Claude Managed Agents — 架构 & 用法

预置的 agent harness 跑在托管基础设施上：你只定义 Agent / Environment，然后开 Session 发 Event。

beta · managed-agents-2026-04-01

它到底是什么

Anthropic 官方对 Claude Managed Agents 的定位是「预构建、可配置的 agent harness，运行在托管基础设施上」，面向长时运行 / 异步任务；而 Messages API 面向「自己写 agent loop、要细粒度控制」。它于 beta，所有端点需请求头 anthropic-beta: managed-agents-2026-04-01。

四个核心概念
  • Agent：模型 + system prompt + tools + MCP servers + Skills，建一次拿到 agent.id
  • Environment：在哪儿跑 —— 托管云沙箱，或自托管沙箱（你自己的 K8s）
  • Session：环境里的一次运行实例，有持久文件系统与事件历史
  • Events：你与 agent 之间的消息（user / agent / session 状态）
能力清单
  • 内置工具：Bash、文件读写/glob/grep、web search & fetch、MCP
  • harness 自带 prompt caching、上下文压缩（compaction）
  • SSE 流式事件；event_deltas 做 token 级预览
  • 旁路能力：Skills、Vaults（凭据）、Memory stores、权限策略、会话预算、cron 定时部署、多智能体编排、Dreams（记忆整理）
什么时候用 / 别用
  • ✅ 跑几分钟到几小时、多轮工具调用的任务；需要沙箱与状态
  • ✅ 不想自己实现 loop、沙箱、工具执行层
  • ⚠️ 不支持 ZDR / HIPAA（自托管版本例外，数据自己存）
  • ⚠️ 仍是 beta，行为可能变；限流：写 300 rpm / 读 1200 rpm

最小用法（五步）

  1. POST /v1/agents → 拿 agent.id（tools 用 agent_toolset_20260401 批量开关）
  2. POST /v1/environments → {"config":{"type":"cloud","networking":{"type":"limited","allow_package_managers":true}}}
  3. POST /v1/sessions → {"agent":…,"environment_id":…,"title":…}
  4. 开 SSE sessions.events.stream()，再 events.send() 发 user.message
  5. 消费事件：agent.message / agent.tool_use … 直到 session.status_idle；中途可发 user.interrupt 或补充消息来纠偏
